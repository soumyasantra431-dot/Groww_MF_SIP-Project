# Groww first-year SIP discovery engine

This is a research workbench for the graduation brief, not an investing assistant. Its job is to examine permitted, source-linked accounts of mutual-fund SIP experiences; show what happened, what remains unknown, and which possible first-year situations deserve further investigation. It does not calculate Groww retention or select a final customer problem.

Start with [Problem Statement.md](Problem%20Statement.md), the [one-LLM architecture](architecture.md), and the [phase-wise implementation plan](implementation-plan.md). The [Phase 0 contract and measured baseline](PHASE_0_CONTRACT_2026-11-04.md) records the current decision, source access states, quality checks and remaining gaps. [Edge cases](edge%20case.md) cover unusual or ambiguous inputs.

**Submission links (9 November 2026):** [Nine-question discovery engine](https://sip-research-viewer.soumyasantra431.workers.dev/) · [Investor-facing SIP Check MVP](https://sip-research-viewer.soumyasantra431.workers.dev/sip-map) · [10-slide case-study PDF](https://sip-research-viewer.soumyasantra431.workers.dev/case-study.pdf) · [AI Evidence Log](deliverables/AI_EVIDENCE_LOG_SUBMISSION.md).

The public engine reports 932 retrieved review IDs, 100 saved public-conversation entries and nine source-linked desk readings. Those are different units and processing stages; they are not 932 analysed investors or a Groww retention estimate. The chosen repair-work situation is a reversible research bet. The MVP's fixed payment map works publicly; AI extraction for new investor text is held after a failed development check. Independent real-item model evaluation, five to six strict-cohort interviews and three target-user MVP tests have not been completed. The deck and Evidence Log state these limits explicitly; no mock account is presented as a participant.

The live Worker is connected to this GitHub repository's `main` branch with `pnpm run build` and `npx wrangler deploy`; preview builds are off. The build order is permitted real-source intake → cleaning and duplicate control → lean one-LLM proposals → human review and nine evidence-bounded answers → independent quality evaluation → local evaluator check → privacy-safe public snapshot. Survey responses stay separate; synthetic examples test code only. No paid model mode is planned.

Run locally with `pnpm.cmd dev`; check code with `pnpm.cmd test` and `pnpm.cmd build`. Regenerate the safe, dated snapshot with `pnpm.cmd snapshot` and inspect it before publication. `public/snapshot.json` is gitignored by default; deliberately stage only a checked release version.
